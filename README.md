# Warifu (割符)

> **Don't trust the agent. Bound it. Prove it. Invite attack.**

**Warifu is the treasurer that cannot be sweet-talked.** An AI agent reads your invoices; a deterministic kernel and an on-chain vault decide; every "no" comes with a reason a human can read; and anyone can try to talk it into paying the wrong person.

The repository, workspace packages and spec ids keep the internal name Symbolon (`@symbolon/*`, INV/K/ATK ids); Warifu is the public name.

## Why
- A ledger cannot see agent errors: the books balance even when the wrong wallet was paid.
- Wallet spending caps cannot see evidence: they bound the damage, not the mistake.
- Circle developer-controlled wallets leave the policy layer to you. The kernel and vault are that layer.

Credit: Canteen's "Agents and Ledgers in 2026" for the error taxonomy.

## How it works
1. **Bound it.** The model extracts and proposes (advisory only, never a release condition). A pure, deterministic kernel (`packages/kernel-core`, checks K-01..K-16) decides. An on-chain vault enforces payee binding, caps and human approval. Payment terms come only from the signed engagement.
2. **Prove it.** Every decision carries a signed, replayable receipt (`pnpm verify-receipt`). The Loss Bound Certificate is recomputed from chain state with `pnpm lbc verify`; it goes STALE when the vault configuration changes. It is a calculation under stated assumptions and exclusions, not a proof.
3. **Invite attack.** The attack suite (ATK-01..24) runs as a regression suite against the real kernel and baselines. The Dojo is a separate, wallet-free sandbox deployment where anyone can try; its traffic is never counted as traction.

The three upgrades on top: the **Seal** (a per-vault badge showing the certificate state), **Nice-try cards** (a templated, shareable one-liner for every rejection; never model prose), and the **Dojo** (the public challenge).

## Disclosures
- **Testnet only.** Contracts are unaudited, hackathon-grade, with tiny caps. Nothing here is a mainnet deployment.
- **Simulated figures.** Attack-suite, honest-corpus and planner numbers come from unit mode: fixture engagements with placeholder signatures and reference extraction reads. No paid LLM run backs any figure; the scoreboard states the number of model calls.
- **Not computed yet** are labelled `NOT_COMPUTED` in the scoreboard (hold-out, certificate, challenge). They are never filled with estimates.
- **Traction** is read from `docs/pilots/pilot_tracker.csv`; a zero is a zero.
- **Attribution.** The escrow design reference and the B0 baseline are Circle's `circlefin/arc-escrow` sample (Apache-2.0). Any file copied from it keeps its original notice; B0 vendoring is tracked as WP-36. B1 is our reimplementation of a pattern, not Circle's code.
- **Language.** We say "calculated from on-chain state and empirically tested", with the assumptions and exclusions next to the number. `pnpm claims:lint` enforces this.

## What `make verify` enforces
- **Purity (INV-8/9/10):** `kernel-core` may not use `Date`, `Math.random`, `fetch`, `process`, Node built-ins, `Number()`, `parseFloat`, `toFixed`, or `any`; money packages may not use floats.
- **Boundaries:** dependency-cruiser forbids kernel-core to extractor/web/services/chain, web to services, packages to apps/services, and cycles.
- **Secrets:** `pnpm test:web-env` fails if `apps/web` references Circle/kernel/guardian secrets or a 64-hex key.
- **Untrusted text is inert (INV-15):** no `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`; challenge/replay code may not import wallet code (INV-16).
- **Claude Code config (SEC-11):** `pnpm claude:check`.
- **Wording and numbers (DEC-012, INV-18):** `pnpm claims:lint` fails on overclaiming words and on any claim-shaped number in README, the public copy files and web content that is not in `results/claims.json`.
