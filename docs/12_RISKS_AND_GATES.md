## 6. Runbooks

**R-KEY: kernel signer compromise suspected.** (1) Guardian `pause()` immediately (kernel or guardian key). (2) Owner `proposeKernelSigner(new)`; wait `signerChangeDelay`; `executeKernelSigner()`. (3) Rotate Circle API key + entity secret; rotate service token secret; redeploy kernel. (4) Review `chain_events` vs `decisions` for unknown releases. (5) Unpause (owner) after reconciler is clean. (6) Document in `docs/INCIDENTS.md`.

**R-BREAKER: breaker tripped.** Read `breaker_state.reason`; inspect `reconciliations`; if false positive, owner signs `/breaker/unfreeze` with reason; if real, follow R-KEY.

**R-CIRCLE: Circle API outage.** Queue releases (idempotent by `intentId`); switch to the fallback relayer only if the owner approves and the outage > 30 min; never double-submit.

**R-LLM: model outage.** Extraction unavailable → no intents; demo uses recorded extraction fixtures (`--recorded`) clearly labeled.

**R-DEPLOY: deadline day.** Freeze `main`; tag `submission-v1`; deploy from the tag; take a snapshot of `/pilot`; export `results/`; record screenshots with timestamps; store in `docs/evidence/`.

**R-FUNDS: tiny mainnet ops checklist.** Fund vault ≤ $200; verify `owner`, `kernelSigner`, `guardian`, caps by reading back immutables; pause/unpause with $1; withdraw test; only then onboard a pilot.

**R-SANDBOX *(v2)*: abuse, exploit or suspected compromise of the challenge.** (1) `CHALLENGE_ENABLED=false` (all challenge routes serve replay mode); (2) guardian `pause()` on the sandbox vault; (3) rotate **sandbox** keys only (service token secret, relayer, kernel signer, Anthropic key); production is untouched by design; (4) export `challenge_attempts` evidence; (5) fix, add the payload to the SEC corpus, re-run SEC suite against the sandbox; (6) rebuild the replay bundle; (7) note in `docs/INCIDENTS.md`. If a real flaw is found by an outsider: thank them (with consent), fix, record it in the known-limits/CHANGELOG.

**R-BUDGET *(v2)*: LLM budget exhausted or provider cap hit.** The service already fails closed to replay (L2); verify the banner, never raise the cap during an attack, review `llm_budget_ledger` by `principal_hash`, and restore at the next day boundary or after Kevin raises the provider-side cap deliberately.

**R-CERT-STALE *(v2)*: certificate shows STALE.** Read the reason(s): `CONFIG_CHANGED`/`ENGAGEMENTS_CHANGED`/`BALANCE_INCREASED`/`FRESHNESS_EXCEEDED`. Verify the change was intended (`ConfigChanged`, `EngagementRegistered`, deposits); rebuild (`pnpm lbc build`), re-run validation if code changed, republish, and keep both certificates. An *unintended* config change is a security incident (R-KEY).
