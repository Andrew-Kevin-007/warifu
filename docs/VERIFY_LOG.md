## V-12 — Circle webhook signature scheme, key retrieval and replay timestamp
**Source**: `services/kernel/src/circle/webhook.ts`, `client.ts` `notificationPublicKey`; from memory, nothing fetched · **Result**: **UNKNOWN (unverified).** Assumed: headers `X-Circle-Signature` (base64) and `X-Circle-Key-Id`; ECDSA with SHA-256, DER-encoded signature, over the raw request body; public key fetched with `GET /v2/notifications/publicKey/{keyId}` as base64 SPKI DER (`data.publicKey`); the body carries `notificationId`, `notificationType` (`transactions.*`), `notification`, `timestamp`. **Replay window**: no header timestamp is assumed to be signed, so the window uses the body `timestamp` (inside the signed bytes). If Circle's curve or signature encoding differs (for example raw r||s), verification FAILS CLOSED (every webhook is refused) until `webhook.ts` is adjusted. The key id header must be in `CIRCLE_WEBHOOK_PUBLIC_KEY_ID` (comma separated); the receiver never fetches a key for an id it was not configured with. **To close**: register the webhook URL on the testnet console, capture one real delivery (headers + body) and one `publicKey` response, and replay them through the shape used in `webhook.local.test.ts`.
